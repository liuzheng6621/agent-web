## agent-web：适配器可插拔（commit 7a7a6f5，已推 Gitee）

**背景**：上一轮已把仓库建起来并推了 95b8f7c（引擎 + 两套同构案例 + FINDING-001）。本轮补的是"别人能不能用"这一环。

**发现的关键缺口**：`bin/agent-web.mjs` 里适配器硬编码成 `ADAPTERS = { memory, taixianglian }`。README 写着"你有一个真实业务系统…先把它写成断言"，但第三方根本接不进来 —— 一个只认自己内置适配器的测试框架只是 demo。

**改动**
- 新增 `src/adapter/load.mjs`：`loadAdapter(spec, options, cwd)` 统一解析内置名 / 文件路径 / 包名；导出解析顺序 `createAdapter()` → `default`（函数/对象）→ 直接导出 `manifest+execute`；加载后跑 `validateAdapter`，不合格直接抛错。
- `isPathSpec` 有一处真 bug 被测试抓到：scoped 包名 `@acme/xxx` 含 `/` 被误判成路径。修法：`if (spec.startsWith('@')) return false;`。
- 新增 `examples/adapter-template/`：仓库出库单骨架（业务故意与咖啡店无关），内置确定性内存后端，约 230 行带注释；`createBackend()` 换 fetch 即真 HTTP。四条案例 + expected.json 覆盖 pass / 负例挡下 / 负例漏挡 / 能力缺口。
- `bin`：`init` 支持 `--adapter`，模板不再生成瞎写的 `expected.json`（改成"先跑后写答案"），模板 `as` 从 `alice` 改角色 `customer`；`verify` 输出补 ✓/✗ 标记。
- `test/engine.test.mjs`：18 → 27 条，新增 5 条加载器用例。

**验证**：`node --test` 27/27；`selftest` 7/7；骨架 verify 4/4 对齐 expected；真实后端 8180 `compare` 跨适配器一致率 100%（7/7）；干净 clone 到临时目录后三条命令全通（证明零依赖、自包含）。

**踩坑**：`picking.submit` → 状态名 `SUBMITTED` 不能靠 `toUpperCase()`，能力名到状态名要显式映射表。

**仍缺**：规范视图写死在代码里（0.2 想改成可声明）；`inferred` 无提级路径；单 run 串行无并发。
