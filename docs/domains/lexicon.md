# 第四个域：词库检索

`cases/lexicon/` + `examples/lexicon/`（实现 A 与 B）。

选它做第四个域，理由和前三个都不一样：**不是为了「再一个不同的业务」，是为了补一个不同的数据形状。**
咖啡、动物、账本三个域的分页断言都只在个位数行上跑过，`total` 说谎、边界丢行、跨页重复
这三种坏法在小数据上每一页都是满的，看着全绿。

| | 前三个域 | 词库域 |
|---|---|---|
| 结果集 | 个位数到几十行 | 900 条，前缀命中固定 30 条 |
| 翻页 | 很少真的翻 | 每页 10 条翻三页，边界必须严丝合缝 |
| 排序 | 按 id 排，天然有序 | 按 rank 排，打乱顺序是常见坏法 |
| 分词 | 无 | 两种算法（贪心 / 反向 DP），切法必须一致 |

## 怎么跑

```bash
node bin/agent-web.mjs verify  cases/lexicon --adapter=lexicon-a
node bin/agent-web.mjs verify  cases/lexicon --adapter=lexicon-b
node bin/agent-web.mjs compare cases/lexicon --adapters=lexicon-a,lexicon-b
node bin/agent-web.mjs certify cases/lexicon --adapter=lexicon-a --detail
```

实测：两个实现各 4/4 与预期一致；`compare` 判决一致率 100%、视图契约兼容；
`certify` 词库域 16 个适用变异体里抓住 10 个（62.5%），最小充分集 6 条断言。

## 这个域抓到的东西

### F1 `pagination` 断言自己有个盲区：从不读实现报的 `total`

这是加这个域最大的收获，而且抓的是**框架自己的 bug**，不是被测系统的。

`certify` 第一次跑只有 5/11，漏网的是 `m-lexicon-total-lies`（前缀命中 30 条、`total` 报 900）。
原因很直接：`src/assert/pagination.mjs` 只做了一件事 —— 把各页行数加起来跟案例声称的
`total` 比。三页各 10 条加起来正好 30，于是判真。**返回体里的 `total` 从来没被读过。**

而 `total` 说谎恰恰是分页最常见、后果最直接的坏法：前端按 900 算出 90 页，
用户翻到第 4 页就是空的，而且每一页的返回都是「对」的。

补法（`pagination_total_reported`）：在数行数之前，先比「实现报的 total」与「案例声称的 total」。
顺序是刻意的 —— 行数对、报数错是最典型的假绿，先报这个才能指出真正的原因。
兼容 `{total}` 与 `{data:{total}}` 两种包裹；实现没报这个字段就跳过，不误判。

### F2 变异体的两层覆盖不够，会出现整片空转

第一版词库域有 8 条断言被 `certify` 标成 `[空转]`（去掉它判决不变）。
补了 5 个变异体之后降到 4 条，剩下的 4 条**全是 `count_delta`**，而且这是框架局限，不是断言写错：

`count_delta` 比的是「终态数 − 初态数」。`wrapState` 型变异体在**每一次** `observe` 上都 tamper，
初始观测也被改了，于是 `(900+1) − (900+1) = 0`，永远抓不住。
要抓它，变异体得知道「这是第几次 observe」—— 那是给变异体开不该开的口子。

记在这里而不是想办法绕过去：`count_delta` 能抓的是**执行层真的多写/少写了一行**，
不是**视图投影时凭空多一行**。两者的差别值得写进断言文档。

### F3 两个实现的算法必须真的不同，否则 `compare` 是自证

实现 A 用字典树 + 正向最长匹配，实现 B 用排序数组二分 + 反向 DP。
如果两边都是「同一个贪心算法换个变量名」，`compare` 一致率 100% 说明不了任何事。

真正被这条约束抓到的地方是**分词样本的选择**：「长江大桥」在两种切法下都是
`['长江','大桥']`（等长），但如果是「长江大桥头」这种，贪心与反向 DP 会分叉。
案例选的样本必须是**切法唯一**的那种，否则一致率是运气，不是契约。

## 还没做的

- **没有真实后端**。这个域的两个实现都是自造的。要接真实后端，最省事的是拿
  `tap` 录一段流量长出孪生，再拿真实服务当第二个实现。
- **写操作完全没有**。词库是纯读域（`lexicon.list` / `lookup` / `segment` 全是 `read`），
  所以 L1（写语义要人给）在这个域上没有任何覆盖。
- **没有中文分词的真实难度**。合成数据里每个词都正好两个字，真实中文有单字词、三字词、
  歧义切分（「乒乓球拍卖完了」）。这个域测的是**分页与结构**，不是分词质量。
- **没有测「前缀命中 0 条」**。字典树与二分在空结果上的行为不同（一个是空数组、
  一个可能返回 `undefined`），这是个值得补的负例。
